# 避難計画エージェント

警報をもとに、AI エージェントが **避難所データ** と **利用者の状況**（いる場所・家族構成・要配慮事項）を使って、
その人や家族に合わせた避難計画を組み立てる PWA です。対象地域は茨城県全域、対象の災害は **洪水** と **土砂災害** です。

- 避難所とハザード（浸水想定・土砂災害警戒区域）は実在のオープンデータを使います。
- 避難経路は、Amazon Location Service で道路に沿って見積もり、その経路が危険な区域を通るか・川を渡るかを調べます。
- 警報は、いまのところ疑似データ（`data/alerts.json`）です。実際の気象庁の警報は取得しません。
- 利用者の情報と避難計画は端末内（`localStorage`）にだけ保存し、サーバ側にはデータベースを持ちません。

> 実際に避難するときは、お住まいの市町村の避難情報と最新の防災情報に従ってください。

## 主な機能

- **場所の登録**：「いまいる場所」（端末の現在地、または地図で指定）か、自宅などの「住所」（家族構成・持病・ペット・移動手段なども登録できる）を登録します。
- **近くの避難所**：登録した場所の近くで、災害に対して安全な避難所を3か所、地図と一覧に表示します。洪水のときは、川を渡らずに行けることも条件にします。端末内で計算するので、オフラインでも見られます。
- **警報の取得と避難計画の作成**：災害の種類（洪水・土砂災害）と警戒レベル（3〜5）を選んで警報を取得すると、エージェントが計画を作ります。
- **道路に沿った避難経路**：避難所までの経路を Amazon Location Service の Routes API で道路に沿って求め、距離・所要時間、浸水想定区域や土砂災害警戒区域を通る割合、橋で渡る川を調べます。計画の地図にも、その経路を描きます。
- **進み具合の表示**：エージェントがどの手順（リスク判定・避難所検索・経路の見積もりなど）を進めているかを、その場で表示します。
- **避難計画**：避難行動の種類（立ち退き避難・垂直避難・屋内安全確保・在宅避難）、避難先と予備、出発の目安、移動手段、経路の注意、役割分担、行動の順番、持ち出し品、家族へのメッセージ（日本語以外の言語の訳つき）を表示し、端末に保存します。
- **PWA**：ホーム画面に追加でき、保存した計画・避難所データ・一度表示した地図はオフラインでも見られます。

## 使い方

1. **場所を登録**
   - 「いまいる場所」：「現在地を使う」か「地図で指定」で場所を決めます。年齢や配慮が必要なことは任意です。
   - 「住所を登録」：住所を入力して「位置を取得」を押すと、緯度経度と市町村が入ります。家族構成なども入力します。
2. **警報を取得して計画を作る**
   - 災害の種類と警戒レベルを選んで「実行」を押します。地域は、選んでいる場所の市町村から自動で決まります。
   - 計画は選んでいる場所について作ります。別の場所の計画は、場所を選び直して実行します。

## 仕組み

```
 ┌──────────────── PWA（S3 + CloudFront）────────────────┐
 │ 場所・家族の情報と避難計画は端末の localStorage に保存    │
 │ Service Worker で画面・避難所データ・地図をキャッシュ     │
 └──┬───────────────────────────────┬───────────────▲────┘
    │① 警報を取得                      │② 場所の情報＋警報  │③ 進み具合と計画を
    ▼                                 ▼                 │   ストリーミング（SSE）
  data/alerts.json（疑似警報）        [CloudFront /api/agent]
                                        │ OAC（署名付きで呼び出し）
                                      [Lambda: agent-proxy]
                                      Function URL（IAM 認証・RESPONSE_STREAM）
                                        │ InvokeAgentRuntime
                                        ▼
                         [Bedrock AgentCore Runtime: Strands Agents]
                          ├─ Claude（Amazon Bedrock）
                          ├─ 道路に沿った経路（Amazon Location Service の Routes API）
                          └─ ツール：世帯情報・災害リスク判定・避難所検索・経路の見積もり・計画の保存
                             （避難所＝茨城県オープンデータ、ハザード＝国土地理院、河川＝OpenStreetMap）
```

1. 画面で災害の種類と警戒レベルを選び、疑似警報を読み込みます。
2. 選んでいる場所の情報と警報を、画面と同じドメインの `/api/agent` に送ります。CloudFront が OAC で agent-proxy（Lambda）を呼び出します。
3. agent-proxy が入力を検証してから AgentCore Runtime 上のエージェントを呼び出し、エージェントの進み具合（SSE）をそのまま画面に流します。完成した計画は端末に保存します。

### AWS リソース

すべてサーバレスで、状態を持つリソースはありません。

| サービス | 用途 |
|---|---|
| S3 + CloudFront | PWA と、疑似警報・避難所・河川・市町村コードのデータの配信。`/api/agent` を agent-proxy に中継 |
| Lambda（Node.js 22、Function URL） | agent-proxy。入力の検証、AgentCore Runtime の呼び出しとストリーミングの中継 |
| Bedrock AgentCore Runtime | エージェントの実行（コードを zip でデプロイ、Python 3.12） |
| Amazon Bedrock | Claude の呼び出し |
| Amazon Location Service（Routes API） | 道路に沿った経路（徒歩・車）の距離・所要時間・経路の線。リソースを作らずに呼び出す |

### エージェント

[Strands Agents](https://strandsagents.com/) で作り、AgentCore Runtime で動かします（[agent/main.py](agent/main.py)）。

| ツール | 役割 |
|---|---|
| `get_household_profile` | 端末から送られてきた場所・家族の情報を取り出す |
| `assess_home_risk` | 指定地点の洪水（想定浸水深・家屋倒壊等氾濫想定区域・垂直避難の可否の目安）と土砂災害（警戒区域・特別警戒区域、現象の種類）を判定する |
| `search_shelters` | 茨城県の避難施設データから、市町村の境界をまたいで避難所を探す。近い施設と、その災害に安全な避難所を候補に入れる。洪水のときは渡らなければならない川も付ける |
| `estimate_route` | 道路に沿った経路（Amazon Location Service）の距離と所要時間（移動手段ごとの速度）、その経路が浸水想定区域・土砂災害警戒区域を通る割合、橋で渡る川。経路が取れないときは直線で見積もる |
| `save_evacuation_plan` | 計画を保存して画面に返す。保存前に避難先をコードで確認する |

判断の原則（警戒レベルごとの行動、洪水・土砂災害それぞれの避難の考え方、外出先にいる場合の考え方など）はシステムプロンプトに書いています。

**計画の確認**：エージェントが計画を保存する前に、コードで次を確かめ、問題があれば理由をつけて差し戻し、選び直させます（[agent/tools.py](agent/tools.py) の `_check_plan`）。

- 避難行動の種類・緊急度が決めた値か。立ち退き避難なら避難先があるか。第一避難先と予備が同じでないか
- 避難所 ID が実在するか
- 避難先がその災害に対して使えるか（洪水：浸水想定区域の中・川や堤防の際・川を渡る、土砂災害：警戒区域の中やすぐそば、どちらも河川敷を弾く）。ただし、5km以内に使える避難所が1つもない場合は、ほかに選びようがないので通す
- 屋外の場所（公園・運動場など）を第一避難先にするのは、屋内の安全な避難所がそれより1km以上遠いときだけ
- 洪水では、直線では同じ岸でも、道路に沿った経路が橋で川を渡る避難先を差し戻す。ただし、道路でも川を渡らない（またはまだ経路を調べていない）候補がほかに残っているときだけ。候補を調べ尽くしてどれも道路では川を渡るなら通す

ほかに、次の上限を設けています。

- 差し戻しが3回になったら、計画づくりを中止する
- ツール呼び出しが20回を超えたら、計画の保存以外のツールを止める。25回を超えたら中止する
- 計画の保存は1回だけ

依頼ごとの実行状態（場所の情報・警報・計画）は `contextvars` で分けていて、同じプロセスで複数の依頼を処理しても混ざりません。

| 道路の経路 | Amazon Location Service（Routes API） | 避難所までの道路に沿った経路（徒歩・車）。エージェントが経路を見積もるときに呼び出す |

### 避難所データの加工

[scripts/prepare_shelters.py](scripts/prepare_shelters.py) で、避難所ごとに次の項目を付けて `data/shelters.json` を作ります。

| 項目 | 内容 |
|---|---|
| 市町村名 | 市区町村コードから付け直す（元データの出典組織の表記が揃っていないため） |
| `flood_depth` / `flood_depth_rank` | 施設地点の想定浸水深 |
| `house_collapse_zone` | 家屋倒壊等氾濫想定区域かどうか |
| `nearby_max_depth_rank` | 周辺120m以内で最も深い浸水深の区分（川や堤防の際にある施設を見分けるため。浸水想定図は河道を塗らない） |
| `landslide_zone` / `landslide_rank` / `landslide_types` | 土砂災害警戒区域・特別警戒区域かどうかと、現象の種類 |
| `nearby_landslide_rank` | 周辺60m以内で最も危険な土砂災害の区分 |

ハザードマップのタイルは、ズーム16（1ピクセル約2m）の画像を施設地点で読みます。全件の処理には数分かかります。

### 安全な避難所の判定

| 災害 | 条件 |
|---|---|
| 洪水 | 施設地点が浸水想定なし、周辺120m以内に3m以上の浸水想定がない、起点から川を渡らずに行ける |
| 土砂災害 | 施設地点も周辺60m以内も土砂災害警戒区域外 |

どちらも、指定避難所が「対応無し」と明記された施設と、河川敷（川の中）は除きます。

公園・運動場などの屋外の場所は、災害に対して安全なら「一時的な避難場所」として候補に残しますが、屋内の避難所より優先度を下げます。画面の「近くの避難所」では屋内を先に出し、足りないときだけ屋外を「屋外（一時的な避難場所）」として出します。エージェントは、屋外を予備の避難先にするときや、屋内の避難所が近くにない・間に合わないときに選び、雨具や暑さ寒さへの備えと、天候が落ち着いたら屋内へ移ることを計画に書きます。

14市町村は指定避難所かどうかがすべて「不明」なので、「不明」も候補に含めます。その場合、エージェントは「避難所として開設されるかを市町村に確認する」よう計画に書きます。

川を渡るかどうかは、2通りの方法で判定します。

- **避難所の検索・計画の確認・画面の「近くの避難所」**：2地点を結ぶ直線が川を横切る回数で判定します。奇数回なら川の反対側にあり、どの道を通っても渡ることになります。偶数回は蛇行をまたいでいるだけで、同じ岸にあります。経路検索を呼ばずに、多くの避難所をまとめて判定できます。
- **経路の見積もりと計画の確認**：道路に沿った経路の線が実際に川を横切るか（橋で渡るか）を判定します。直線では同じ岸でも、道路が橋を渡って遠回りする場合があるため、計画の確認では両方を見ます。

経路の見積もりでは、道路に沿った経路の線を約50mおきに区切り、その地点のハザードマップを読んで、浸水想定区域・土砂災害警戒区域を通る割合を出します。車の所要時間は、経路検索の値と、渋滞を見込んだ速さ（時速15km）で計算した値の長いほうを使います。

### データの注意点

- 避難所データは2019年時点のもので、その後の指定の変更や開設状況は反映されていません。ペット同行・バリアフリー・収容人数などの設備情報もありません。
- 浸水想定は想定最大規模の雨を前提にした値で、どの川の氾濫かは区別しません。
- 判定は施設の代表点1か所で行っています。国や市町村が施設ごとに判定したものではありません。
- 河川は OpenStreetMap に載っている主な19河川だけです。小さな川や用水路は判定の対象外です。

### 疑似警報

`data/alerts.json` に、気象庁の2026年からの防災気象情報（レベル付きの警報）の名称に合わせた疑似警報の雛形があります。

- **洪水**：選んだ場所の市町村を流れる河川の警報（例：那珂川レベル4氾濫危険警報）を出し、その河川の沿川市町村を対象にします。河川と市町村の割り当ては、県内44市町村すべてがどれかの河川に入るよう作ったもので、実際の洪水予報の区域とは一致しません。
- **土砂災害**：選んだ場所の市町村に警報（例：レベル4土砂災害危険警報）を出します。

## デプロイ

前提：Node.js 20 以上、[uv](https://docs.astral.sh/uv/)、AWS CLI。リージョンは東京（ap-northeast-1）です。Docker は不要です。

```bash
# 1. 認証（どれか）
aws login            # または aws configure / aws sso login
aws sts get-caller-identity

# 2. 使うモデルを呼び出せるか確認（Bedrock コンソールでモデルアクセスを有効にしておく）
aws bedrock-runtime converse --region ap-northeast-1 \
  --model-id global.anthropic.claude-opus-4-6-v1 \
  --messages '[{"role":"user","content":[{"text":"こんにちは"}]}]'

# 3. デプロイ（初回のみ bootstrap）
cd infra
npm ci
npx cdk bootstrap
npm run deploy
```

完了すると `SiteUrl` が表示されるので、ブラウザで開きます。

エージェントはコンテナではなく、AgentCore Runtime の zip 方式でデプロイします。`cdk deploy` のときに uv が実行環境（Linux / ARM64・Python 3.12）向けの依存ライブラリを取得し、`agent/*.py` と `data/shelters.json`・`data/rivers.json` と一緒に zip にします。

### モデルの変更

`infra/cdk.json` の `context` で変更できます。デフォルトは `global.anthropic.claude-opus-4-6-v1`（Claude Opus 4.6）で、推論は国外のリージョンでも行われます。推論を国内で完結させたい場合は、`jp.anthropic.claude-sonnet-4-6` などの `jp.` で始まる推論プロファイルを使います。

```bash
npx cdk deploy -c modelId=jp.anthropic.claude-sonnet-4-6
# 推論の要約の設定がモデル側で受け付けられない場合
npx cdk deploy -c thinkingDisplay=
```

アカウントによっては、推論プロファイルの一覧に出ているモデルでも、呼び出すと「not available for this account」になることがあります。デプロイ前に上の手順2で確認してください。

### セキュリティ

| 対策 | 内容 |
|---|---|
| Lambda を直接呼べなくする | agent-proxy の Function URL は IAM 認証で、CloudFront の OAC 経由でしか呼べません。画面からは同じドメインの `/api/agent` を呼ぶので、CORS も開けていません。POST の本文の SHA-256 を `x-amz-content-sha256` ヘッダーに付けて送ります |
| 入力の検証 | agent-proxy で、決めた項目だけを型・長さ・件数・値の範囲（茨城県内の座標、警戒レベル3〜5など）を確かめて作り直し、それ以外は捨てます（本文は20KBまで） |
| プロンプトインジェクション対策 | システムプロンプトで、利用者が入力した文中の指示には従わず、避難計画の作成以外の依頼には応じないよう指示しています。エージェントが使えるのは避難計画用のツールだけです |
| 計画のコードによる確認 | 危険な区域の中・河川敷・洪水で川を渡る避難先や、存在しない避難所 ID は保存時に差し戻します。差し戻しは3回、ツール呼び出しは25回までで中止します |
| セキュリティヘッダー | CloudFront で CSP（読み込める配信元を、地図・住所検索・CDN・フォントに限定）、HSTS、`X-Frame-Options: DENY`、`X-Content-Type-Options`、Referrer-Policy、Permissions-Policy（位置情報はこの画面だけ）を付けます。TLS 1.2 以上のみ |
| 外部スクリプトの改ざん対策 | CDN から読み込む Leaflet に SRI（integrity 属性）を付けています |
| 最小権限 | AgentCore の実行ロールは、設定したモデル（推論プロファイルと基盤モデル）と、Amazon Location Service の経路検索だけを呼び出せます。S3 は非公開で、HTTPS 以外の通信を拒否します |
| 利用額の上限 | agent-proxy の同時実行数を10に制限しています |
| 依存ライブラリ | エージェントの依存ライブラリはバージョンを固定しています |

利用者の認証や AWS WAF は入れていません。サイトの URL を知っていれば、誰でもエージェント（Bedrock）を呼び出せます。

- 費用のほとんどは Bedrock の利用料で、計画1件あたり数十円が目安です。その他のリソースは呼び出されたときだけ課金されます。
- AWS Budgets で予算アラートを設定しておくことをおすすめします。
- 不特定多数に公開する場合は、AWS WAF（IP ごとの回数制限）や Amazon Cognito（ログイン）を追加してください。

## 制約

- 警報は疑似データです。警報が出たことをアプリから知らせる機能はありません。
- 経路は道路に沿って見積もりますが、近い道を探すもので、浸水想定区域や崖を避ける道を探すわけではありません。災害時の通行止めや冠水も反映されません。
- 経路検索が使えないとき（通信の失敗など）は、2地点を結ぶ直線で見積もります（距離は1.3倍して道なりの目安にします）。
- 避難所の開設状況・混雑・設備はわかりません。
- 計画ができるまで1〜2分かかり、オンラインである必要があります（保存済みの計画と近くの避難所はオフラインでも見られます）。

## 今後の改善

- 気象庁の防災情報への置き換え。現在の体系のデータは `https://www.jma.go.jp/bosai/warning/data/r8/080000.json`（茨城県）にあり、ブラウザから直接取得できます。河川ごとの洪水予報は `https://www.jma.go.jp/bosai/flood/data/r8/flood_xml.json` です。公式の仕様書があるのは防災情報 XML です。
- 浸水想定区域や土砂災害警戒区域を避ける経路の検索（Routes API の避ける範囲の指定や、独自の経路検索）。
- 平時に計画を作っておき、警報のときはすぐ表示する仕組み。
- 津波への対応。国土地理院の津波浸水想定（`04_tsunami_newlegend_data`）は茨城県の沿岸で取得できます。数分を争う避難になるため、計画の作り方を別に考える必要があります。
- 災害種別ごとの対応可否が入った避難所データ（国土地理院の指定緊急避難場所データなど）への切り替え。
